# QA before every push

Pushing `main` deploys. There is no staging. This is the minimum pass, and it has caught a real
problem every time it was run (clipped caption, misaligned headline, clipped hero label, phone
spacing, mismatched card rows).

## 1. Serve locally

`.claude/launch.json` defines a `portfolio` preview that runs `python -m http.server 8765` from
the repo root. Any static server works. On the original laptop a server on 8765 was often
already running from an earlier session; reuse it.

## 2. Render at two widths

`tools/qa_render.py` drives headless Edge, saves a full-page PNG, and cuts it into viewable slices
under `tools/out/`. Default pages: home at 1280 and 375, plus any path you pass.

```bash
python -I tools/qa_render.py http://localhost:8765/ http://localhost:8765/mllmjudge/
```

Look at every slice. Things to check:

- Headline left edge lines up with "Project Highlights" (both 140px from the left at 1280).
- Both Project Highlights rows have identical card widths and left edges.
- Related Links captions fit their cards (the arXiv card has a two-line title and the least room).
- Hero labels are not clipped under the nav.
- Prose paragraphs sit between heading and figure on case study pages.

Headless Edge quirks: it writes nothing if another headless instance holds the same
`--user-data-dir`, so the script uses a fresh directory per run. The 375px headless render does
not emulate a phone and can look overflowed; trust the pane emulator for phone layout.

## 3. Measure in the desktop app's browser pane

The pane's screenshots time out often, but its JavaScript tool is reliable. Use it for:

- `document.documentElement.scrollWidth === innerWidth` at 375 (no horizontal overflow).
- Card widths per row: `[...document.querySelectorAll('.nYycZgH4dD > .inst')]` versus
  `.ng4mm69FI1 > .inst`.
- Slider: set the range value, dispatch `input`, confirm `--pos` follows.
- Phone nav link colour: `.nav-phone-links a` should compute to `rgb(255, 255, 255)`.

Set the pane to the mobile preset for phone checks and back to desktop when done.

## 3b. Figure audit (no image may be cropped)

Every content figure is a CSS background image. `assets/figures.css`, generated by
`tools/fix_figures.py`, pins each one to its image's own aspect ratio with `background-size:
contain`, per breakpoint (see [[site-structure]]). After touching any page, re-run the generator
and the audit:

```bash
python -I tools/fix_figures.py
```

The generator also writes `tools/out/figure_sizes.json` and the audit snippet is built from it
(the 2026-10-10 session kept it in `tools/out/audit.js`). In the pane's JavaScript tool, store the
sizes map in `sessionStorage.S` and the snippet in `sessionStorage.AUD` once per origin, then on
each page at 375, 1000 and 1280 run `eval(sessionStorage.AUD)`. The result line must read
`CLIPPED=[] zero=[]` on every page. `CLIPPED` lists figures whose box ratio is more than 3 percent
off the image ratio while still on `cover`; `zero` lists figures that collapsed to nothing, which
is what happens when a height-driven box gets `height:auto` or a width-driven one gets
`width:auto`. The generator handles both drivers, per media block, and keeps slideshow slides at
the frame height.

## 4. Text checks

`tools/bump_version.py --check` reports em dash counts, U+FFFD counts, the `?v=` versions on each
page, and the number of gallery links per footer variant. All pages must agree on versions and
have seven gallery links in every variant.

## 5. After push

```bash
curl -s "https://reubenluera.github.io/?cb=$RANDOM" | grep -o 'base.css?v=[a-z0-9]*'
```

Poll until the version matches, usually 10 to 70 seconds. For a new share image, also fetch
`assets/og.jpg?v=N` and confirm a 200.
