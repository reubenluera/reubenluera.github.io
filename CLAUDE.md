## What this site is for

The audience is a recruiter or hiring manager who has 90 seconds. The site has one job: make
"AI UX Researcher" land in the first screen and back it with evidence. Every change is judged
against that. See [[decisions]] for why the site looks the way it does.

The pages were generated from the Framer project, so class names are hashed (`nYycZgH4dD`) and
each page carries its own `<style>` block with four breakpoints: base (1200 to 1727px),
`min-width: 1728px`, `810px to 1199.98px`, and `max-width: 809.98px`. Hand-written CSS goes in
`assets/base.css`, not into the generated blocks, unless a generated rule itself is wrong.
[[site-structure]] maps the parts that matter.

## Hard rules

1. **No em dashes.** Not in HTML, CSS comments, commit messages, wiki pages, or anything else.
   Check with a U+2014 count before committing. Older case study pages still contain some from
   the Framer export; remove them when you touch those pages, do not add new ones.
2. **Real text over baked text.** Anything a recruiter should be able to read, search, or copy is
   HTML text. Words painted into images (the hero labels) are decoration and must be duplicated
   as text somewhere on the page.
3. **Never edit a Framer-exported image in place.** Generate a derived file with a new name,
   reference it with a `?v=` suffix, and keep the generator in `tools/`.
4. **Cache-bust on every asset change.** `base.css?v=`, `site.js?v=`, hero images and `og.jpg`
   each carry a version suffix. Bump it on all seven pages in the same commit, or the live site
   serves stale files for days.
5. **Preserve line endings.** `site.js` and the HTML pages are CRLF, `base.css` is mixed. Scripts
   open files with `newline=''` and write back exactly what they read. Never let a tool normalise
   a whole file.
6. **QA before push, at two widths.** Desktop (1280 or 1440) and phone (375). Pushing `main` is
   deploying; there is no staging. The procedure is in [[qa]].
7. **Verify live after push.** `curl` the page for the new version string and confirm the deploy
   landed (usually 10 to 70 seconds). Do not report done on a push alone.
8. **Absolute URLs use `https://reubenluera.github.io/`.** Open Graph tags, the share image, the
   README. Relative paths everywhere else so the site works at any root.
9. **Leave the `benluera` account alone.** `benluera.github.io/halo-prototype` and
   `/pc-settings-screens` are live UserTesting stimulus URLs for HP studies. Never rename that
   account or touch those repos from here.
10. **Experiments go on branches.** Keep them merged up to date with `main`. `hero-overlay` is one
    such branch and is unmerged on purpose until the human decides.
11. **No image is ever cropped.** The human was explicit: the whole image must be visible at every
    window size. Content figures are pinned to their image ratio by the generated
    `assets/figures.css`. After any page edit, re-run `tools/fix_figures.py`, bump its `?v=`, and
    run the figure audit in [[qa]] at 375, 1000 and 1280. `CLIPPED=[] zero=[]` or it does not ship.

## Workflows

**Content or style change**
1. Edit on `main` (or a branch for anything the human has not approved yet).
2. Bump the relevant `?v=` suffixes on all pages.
3. Run the QA pass in [[qa]]: headless Edge renders at 1280 and 375, plus the pane's phone
   emulator for the slider and nav.
4. Commit with a plain-English message, push, verify live with `curl`.
5. Append a line to `wiki/log.md`. If the change was a decision, add it to [[decisions]].

**Regenerating the hero**
The two hero layers are derived from two Framer images. `tools/hero_relabel.py` repaints the side
labels, `tools/hero_toplabel.py` adds the centred role label, `tools/og_image.py` rebuilds the
share image from the result. Run them in that order. Details and the measurements they depend on
are in [[hero-pipeline]].

**Adding a case study**
Copy the shape of `optimizing/index.html` (at-a-glance block, "What happened" bullets, prose under
each figure heading). Then: add a card to the correct row container on the home page (the two
rows are separate flex containers, see [[site-structure]]), add the page to every footer gallery
on all pages, add Open Graph tags with the absolute URL, and update the project nav links on the
neighbouring case studies.

**Picking up on a new machine**
Clone the repo, open the folder, read this file and `wiki/index.md`. Python 3 with Pillow and
NumPy covers the tools. Headless rendering uses Microsoft Edge on Windows; on another OS swap in
Chrome with the same flags. The generator scripts reference Windows system fonts (Arial Black,
Segoe Print Bold, Segoe UI Bold); on another OS point them at equivalent files.

## Things that bit us already

- The four Project Highlights cards are two separate flex rows. At tablet widths the second row
  had a different width than the first, so its cards shrank. Fixed, but any new card has to go in
  the right container.
- The nav bar is fixed and overlaps the top few pixels of the hero. Anything painted near the top
  edge of the hero image gets clipped. Keep hero labels at y 60 or lower in the 962px tall source.
- The desktop app's browser pane throttles animation frames and often times out on screenshots.
  Use it for DOM measurements with the JavaScript tool; use headless Edge for pictures.
- Headless Edge silently produces no file if another headless instance holds the same profile
  directory. Use a fresh `--user-data-dir` per run.
- Bash heredocs in the agent harness mangle backslashes. Write Python helpers to files with the
  Write tool and run them with `python -I path`.
- LinkedIn, Slack and iMessage cache link previews by URL. Changing `og.jpg` means changing its
  `?v=` suffix on every page, and LinkedIn still needs its Post Inspector run once.
